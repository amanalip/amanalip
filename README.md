## Recent Open-Source Projects

### [PipeViz](https://github.com/amanalip/PipeViz)

PipeViz is a browser-based Jenkins pipeline visualizer. You can paste or upload a Jenkinsfile and inspect the pipeline as an interactive graph without sending the file to a backend.

The project handles declarative stages, parallel branches, matrix configurations, nested stages, conditions, steps, agents, environment values, parameters, triggers, post handlers, and other pipeline metadata. It also includes source-linked diagnostics, matrix expansion, inspectors, PNG export, shareable links, light and dark themes, keyboard-accessible source navigation, and safeguards for large or partially parsed files.

I built PipeViz with React, TypeScript, Vite, React Flow, and CodeMirror. The repository also includes automated tests and a GitHub Actions workflow that builds and deploys the application to GitHub Pages.

### [Token Trail](https://github.com/amanalip/tokentrail)

Token Trail is a privacy-first desktop dashboard for understanding local Codex usage. It presents available usage windows, token activity, reset information, credits, and related metrics in a desktop interface rather than making users piece that information together manually.

Version 1.0.0 was released on August 22, 2026 and completes the approved read-only scope. The application is built with Electron, React, TypeScript, Vite, ECharts, and Zod. It has separate main, preload, and renderer builds, along with integration, accessibility, end-to-end, security, packaged-application, performance, and coverage testing.

The project also has documented architecture, data flow, threat modelling, protocol compatibility, privacy boundaries, and packaging workflows. Signing, automatic update deployment, telemetry, and broader Codex access are intentionally outside the current released scope.

### [Code Explorer](https://github.com/amanalip/code-explorer)

Code Explorer is a browser-based Python learning platform built around a simple idea: seeing the final output is useful, but understanding how the program reached that output is often more valuable.

Learners can write or paste Python code, run it locally in the browser, and move through a recorded execution step by step. The main Python workspace contains 134 programs and includes execution tracing, variable and data-structure views, control-flow analysis, replay breakpoints, code coverage, loop inspection, input comparisons, trace bookmarks, learning comments, and debugging tools.

The project also has a separate Data Structures and Algorithms workspace with 535 reviewed and executable programs across 25 curriculum sections. Its 18 learning views are designed to help learners inspect structure state, execution behaviour, algorithm context, complexity, comparisons, and changes caused by different inputs.

### [Termodoro](https://github.com/amanalip/Termodoro)

Termodoro is an offline Pomodoro timer and task manager for the terminal, written in Rust with Ratatui and Crossterm.

It combines configurable focus sessions with task management, productivity history, streak tracking, themes, desktop notifications, keyboard-driven navigation, and local persistence. The project is structured as a modular Rust application and includes automated testing, CI, documentation, and a local-first design with no application telemetry.

Building Termodoro gave me a chance to work more deeply with Rust, terminal interfaces, application state, persistence, event-driven interaction, and the design of software that stays useful without depending on a cloud service.

### [TermLeaf](https://github.com/amanalip/TermLeaf)

TermLeaf is a terminal-based reader that I am actively developing in Rust. The aim is to make local reading comfortable for people who spend much of their time at the command line.

Phase 0 and Phase 1 are complete, and Phase 2 development is underway. The current implementation includes bounded Markdown and EPUB handling, internal navigation, archive and XML safety controls, raster and SVG decoding, terminal image capability selection, fallbacks for terminals without image support, and a responsive table of contents.

The broader project is being designed around TXT, Markdown, and reflowable EPUB reading, with saved reading positions, bookmarks, highlights, notes, search, responsive layout, and keyboard-first navigation. I keep planned work separate from what is already implemented so the repository status remains clear.

### [cloudservs](https://github.com/amanalip/cloudservs)

cloudservs is an in-development cloud learning project. The goal is to teach a cloud concept in vendor-neutral terms first, then show how AWS, Microsoft Azure, and Google Cloud implement the same idea.

The full curriculum is not complete. The repository currently tracks a planned 93-lesson curriculum across nine modules, with three lessons completed through the project's quality and verification process. The underlying learning platform is already taking shape with Astro and Starlight, Pagefind search, local lesson progress, knowledge checks, provider comparisons, ASCII and Mermaid diagrams, accessibility-focused interactions, privacy validation, and Playwright regression tests.

I am developing the project gradually because the content itself matters as much as the software. Each completed lesson is intended to be technically reviewed, sourced, tested in the interface, and clearly separated from material that is still planned.
