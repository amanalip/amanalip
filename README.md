## Recent Open-Source Projects

### [PipeViz](https://github.com/amanalip/PipeViz)

PipeViz is a browser-based Jenkins pipeline visualizer. You can paste or upload a Jenkinsfile and inspect the pipeline as an interactive graph without sending the file to a backend.

The project handles declarative stages, parallel branches, matrix configurations, nested stages, conditions, steps, agents, environment values, parameters, triggers, post handlers, and other pipeline metadata. It also includes source-linked diagnostics, matrix expansion, inspectors, PNG export, shareable links, light and dark themes, keyboard-accessible source navigation, and safeguards for large or partially parsed files.

I built PipeViz with React, TypeScript, Vite, React Flow, and CodeMirror. The repository also includes automated tests and a GitHub Actions workflow that builds and deploys the application to GitHub Pages.

### [Token Trail](https://github.com/amanalip/tokentrail)

Token Trail is a privacy-first desktop dashboard for understanding local Codex usage. It presents available usage windows, token activity, reset information, credits, and related metrics in one desktop interface.

Version 1.0.0 was released on August 22, 2026 and completes the approved read-only scope. The application is built with Electron, React, TypeScript, Vite, ECharts, and Zod. It has separate main, preload, and renderer builds, along with integration, accessibility, end-to-end, security, packaged-application, performance, and coverage testing.

The project also documents its architecture, data flow, threat model, protocol compatibility, privacy boundaries, and packaging workflows. Signing, automatic update deployment, telemetry, and broader Codex access are outside the current released scope.

### [Code Explorer](https://github.com/amanalip/code-explorer)

Code Explorer is a browser-based Python learning platform that shows how a program executes step by step instead of only showing the final output.

Learners can write or paste Python code, run it locally in the browser, and move through a recorded execution one step at a time. The main Python workspace contains 134 programs and includes execution tracing, variable and data-structure views, control-flow analysis, replay breakpoints, code coverage, loop inspection, input comparisons, trace bookmarks, learning comments, and debugging tools.

The project also has a separate Data Structures and Algorithms workspace with 535 reviewed and executable programs across 25 curriculum sections. Its 18 learning views help learners inspect structure state, execution behaviour, algorithm context, complexity, comparisons, and changes caused by different inputs.

### [Termodoro](https://github.com/amanalip/Termodoro)

Termodoro is an offline Pomodoro timer and task manager for the terminal, written in Rust with Ratatui and Crossterm.

It combines configurable focus sessions with task management, productivity history, streak tracking, themes, desktop notifications, keyboard-driven navigation, and local persistence. The project is structured as a modular Rust application and includes automated testing, CI, documentation, and a local-first design with no application telemetry.

I built Termodoro partly to get deeper practical experience with Rust, terminal interfaces, application state, persistence, and event-driven interaction.

### [TermLeaf](https://github.com/amanalip/TermLeaf)

TermLeaf is a terminal-based reader that I am actively developing in Rust. It is intended for reading local books and documents without leaving the terminal.

Phase 0 and Phase 1 are complete, and Phase 2 development is underway. The current implementation includes bounded Markdown and EPUB handling, internal navigation, archive and XML safety controls, raster and SVG decoding, terminal image capability selection, fallbacks for terminals without image support, and a responsive table of contents.

The longer-term plan covers TXT, Markdown, and reflowable EPUB reading, along with saved reading positions, bookmarks, highlights, notes, search, responsive layout, and keyboard-first navigation. Planned work is kept separate from completed implementation in the repository documentation.

### [cloudservs](https://github.com/amanalip/cloudservs)

cloudservs is an in-development cloud learning project. The goal is to explain a cloud concept in vendor-neutral terms first, then compare how AWS, Microsoft Azure, and Google Cloud implement it.

The curriculum is not complete. The repository currently tracks a planned 93-lesson curriculum across nine modules, with three lessons completed through the project's quality and verification process. The current platform uses Astro and Starlight and includes Pagefind search, local lesson progress, knowledge checks, provider comparisons, ASCII and Mermaid diagrams, accessibility-focused interactions, privacy validation, and Playwright regression tests.

I am developing the content and the platform together. Completed lessons are reviewed, sourced, tested in the interface, and tracked separately from material that is still planned.
